# 各版本教材研究與 LLM 融合工作流

## 目的

`full-lesson-v1` 只證明 lesson 具備較完整的資料結構與教學階段，不證明已讀完各版本教材。新的 `version-fused-v1` 才代表完成逐版本研究、LLM 融合與 Terra 第二輪 AI 複核。

## 每個單元的輸入

1. 官方課綱與穩定 Knowledge Graph ID。
2. 南一、康軒、翰林及必要時翰林／佳音英文體系的可取得版本資料。
3. 下載檔案的本機受控快取，或網頁 URL、章節／頁碼定位、查核日期與授權狀態。
4. 合法公開的會考、公立國中考題只作能力與題型研究；題庫仍須獨立命題。

來源快取由 `data/version-source-manifest.json` 管理；執行 `python3 scripts/verify_version_sources.py` 可確認 manifest 指向的本機檔案存在且非空。若 manifest 記錄檔案大小或 SHA-256，工具也會核對。驗證來源可讀不等於完成逐單元研究、LLM 融合或 Terra 複核。

## 版本研究最小內容

每一版本至少記錄概念／知識順序、術語、圖表或符號表徵、例型／資料證據、常見迷思、活動與評量重點。數理科特別記錄公式條件、推理步驟、量與單位、模型限制及變式；社會科特別記錄時間線、空間尺度、史料或統計資料、因果關係、觀點差異及證據限制。

語文科另記錄篇名、作者、文體、各段重點、結構、作者意圖、主旨、觀點、修辭、重要字詞與版本注釋涵蓋範圍。文言文的原典與現代翻譯、標點、注釋分開判定；注釋與翻譯沒有授權時，改用 AI 原創文字。

## LLM 融合輸出

LLM 必須先整理各版本共同核心與差異，再針對每一個單元獨立產出原創正文、具體自編例子、錯誤診斷、遷移任務、摘要、離堂檢核與題目。不得以單一版本、章節索引、批次通用句或共用正文骨架取代研究。`scripts/enrich_full_lessons.py` 僅保留作歷史資料遷移，預設拒絕執行，不能作為新教材產生器。

lesson 使用 `authoringStandard=version-fused-v1`，並提供 `versionResearch` 與 `fusionRecord`。題目必須連回融合後的 KG 概念與正文，具備答案、完整解析與錯誤選項理由。

## 審查與狀態

第一輪 AI 檢查內容正確性、單元符合度、來源定位、原創性、答案唯一性、重複題與模板重用；第二輪優先使用 Terra model 複核。任一版本研究、融合或複核缺失，維持 `draft`。`scripts/audit_version_fusion.py --strict` 用來阻止未遷移的 reviewed lesson 被誤當成完成。
